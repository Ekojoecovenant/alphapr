The comment lands on line 44.

02 / how it works

Connect. Review. Remember.

  1. 01

    Connect

    Install the GitHub App, then paste your provider key on /setup. The key is yours, stored against your installation, and used only for that installation's reviews.

    github.com/apps/alphapr-ai
  2. 02

    Review

    AlphaPR reads the diff and validates every line number before it comments, so a finding always points at the line it describes — with a GitHub suggestion the author can commit in one click.

    diff in / comments out
  3. 03

    Remember

    Only new commits are reviewed. The last reviewed SHA is stored per PR, so pushing a commit you already pushed is skipped as "Already reviewed" instead of buying the same tokens twice.

    last SHA per PR

03 / setup

Your key. Your model. Your thresholds.

One server-rendered page per installation. No SPA, no client router, no state to lose — the form is a template string with your installation's current values already in it.

  • Bring your own key. OpenRouter is verified in production; Anthropic and OpenAI are contract-tested, not yet live-verified.
  • Two run modes. Cloudflare Queues, or the free tier that retries once when the first attempt fails fast.
  • Quiet by default. Draft PRs wait until they are ready for review, and [skip alphapr] in the PR title skips the run entirely.

Design notes
  1. Palette. A green-black instrument panel, not a generic dark SaaS: #0d1112 canvas, #141a1c surfaces, one teal signal at #3acbb9. Amber is reserved for "in progress", red for failure, so a colour always means one thing.
  2. Motion budget. One canvas at 60fps (~27 draw calls), group spin at 0.06 rad/s plus pointer parallax clamped to ±6°. rAF stops when the panel is offscreen or the tab is hidden; the only CSS animation is the 1.6s in-progress dot. Under reduced motion the scene draws one frame and rAF never starts.
  3. Cheap to port. Type scale, hairline system, diff rows, label/field grid and the three state cards are plain markup inside src/setup-pages.ts template strings — one ~190-line module returning strings, no framework, one <style> block, no bundler.
  4. Expensive to port. The scene itself is roughly 250 lines of three.js plus a hand-drawn SVG fallback, and the CDN script is the page's largest dependency. It is worth it only on the marketing page, never inside /setup.
  5. Accessibility. Worst text pair (muted on raised) is 5.6:1; every other pair is higher. Focus ring is 2px at 3px offset. The canvas carries a text alternative and the panel has mono captions; the status dot is never the only signal because the label names the state. Form controls keep real labels and a native submit.
  6. Honest weakness. The field is atmosphere, not information — it makes the product feel like a 2026 tool without explaining what it does. Offline it degrades to a flat SVG, which is honest but less persuasive, and the 3D budget buys nothing for a returning user.
  7. Failure copy. The provider's message sits in a mono blockquote with a red left rule; the ⚠️ is product output, not marketing chrome. Everywhere else on the page uses stroke icons.

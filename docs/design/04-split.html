ALPHAPR

A BYOK AI PR reviewer that comments on the exact lines it's talking about — and remembers what it already said.

Install the app, paste a provider key, pick a model. AlphaPR reads the diff, checks every line number before it comments, and stores the commit it reviewed so the next push only gets the new part.

02 / how it works

Three moves, no dashboard.

There is no new tab to live in. AlphaPR sits where the review already happens: the GitHub App, the pull request, the commit SHA.

  1. 01

    Connect

    Install the GitHub App, then paste your provider key on /setup. OpenRouter is verified in production; Anthropic and OpenAI are implemented and contract-tested, but not yet live-verified.

    github.com/apps/alphapr-ai

  2. 02

    Review

    AlphaPR reads the diff and validates every line number before it comments, so a finding can’t drift onto the wrong line. Findings land as inline threads with suggestion blocks.

    severity · tone · ignore paths

  3. 03

    Remember

    The last reviewed commit is stored per PR. A re-push reviews only new commits; an identical SHA is skipped as “Already reviewed”, and a draft waits until it is ready.

    drafts skipped · [skip alphapr] honoured

Design notes
  • Palette rationale. Paper and ink carry the page; teal is structure and action, never decoration. Orange is reserved for Apply suggestion and the one finding slab in the 3D scene, so the action that looks irreversible owns the warmest pixel on the page. Severity reds and ambers never leave review chrome.
  • Motion budget. One three.js scene (9 slabs, a wireframe anchor, an 8s ±0.05rad oscillation), a 900ms teal flash on Apply, a 1.6s pulse on the in-progress dot, and 140–160ms hover/theme transitions. The rAF loop stops when the panel is offscreen or the tab is hidden.
  • Reduced motion. The scene renders exactly one static frame and never starts rAF; the flash becomes a steady 2px teal border; the dot stops pulsing; smooth scroll and all transitions are disabled.
  • Cheap to port into src/setup-pages.ts. Tokens, grid and form styles are plain CSS; the whole theme is one attribute; the review card and setup form map directly onto template strings. No build step, no framework.
  • Expensive to port. The three.js panel: a ~600KB CDN dependency, a hand-built fallback, and theme-aware material updates. If budget is tight, ship the fallback SVG and drop the live scene.
  • Accessibility. Real links and buttons, 2px focus rings at 3px offset, aria-live on the Apply result, aria-pressed on the toggle, labelled form controls, a text caption for the canvas, and contrast checked in both themes.
  • Honest weakness. The split hero and 3D panel are the most expensive pixels for the least product information. On a cold connection the panel sits as a static SVG until three.js arrives and swaps in; the layout still works, but the first impression is thinner than the concept claims.
